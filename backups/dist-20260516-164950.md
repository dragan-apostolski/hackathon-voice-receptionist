## Patch 6 — `src/services/availabilityService.ts`: replace `TZDate` with plain local-time construction

**File:** `src/services/availabilityService.ts`

Renderer used `TZDate` from `date-fns-tz` v3 as a constructor (`new TZDate(date, TIMEZONE)`) to
combine a date and a time string. `TZDate` is not callable as a constructor in the webpack/Next.js
RSC bundle. First fix used `fromZonedTime` — but that caused a **second bug**: incoming datetimes
are parsed with `parseISO` as server-local time, while `fromZonedTime` converted working hours
from the practice IANA timezone (e.g. `America/New_York`) to UTC. When server timezone ≠ practice
timezone (e.g. user on PDT), 14:30 PDT = 21:30 UTC was outside 17:00 EDT = 21:00 UTC, producing
spurious 409 "slot unavailable" errors.

Final fix: drop `date-fns-tz` entirely; build the combined date by cloning the reference `Date`
and setting hours/minutes in the same local timezone that `parseISO` uses. Both sides of every
comparison now operate in the same frame of reference.

```diff
-import { TZDate } from "date-fns-tz"; // was: original renderer
-import { fromZonedTime } from "date-fns-tz"; // was: first fix attempt
-const TIMEZONE = process.env.PRACTICE_TIMEZONE || "America/New_York";

 private combineDateAndTime(date: Date, timeStr: string): Date {
-  const [hours, minutes] = timeStr.split(":").map(Number);
-  const d = new TZDate(date, TIMEZONE);
-  d.setHours(hours, minutes, 0, 0);
-  return d;
+  const [hours, minutes] = timeStr.split(":").map(Number);
+  const result = new Date(date);
+  result.setHours(hours, minutes, 0, 0);
+  return result;
 }
```

## Patch 7 — multiple API routes: sync `params` access (Next.js 15 requires `await params`)

**Files:** `src/app/api/calls/[id]/route.ts`, `src/app/api/staff/[id]/route.ts`,
`src/app/api/staff/[id]/working-hours/route.ts`, `src/app/api/working-hours/[id]/route.ts`

Next.js 15 wraps dynamic route `params` in a Promise. Accessing properties synchronously
(even via destructuring) throws a runtime error. Renderer emitted the old sync pattern
`{ params }: { params: { id: string } }` in four route files.

```diff

+{ params }: { params: Promise<{ id: string }> }

-const { id } = params;

```

## Patch 11 — `src/app/admin/staff/[staffId]/hours/page.tsx`: extract `staffId` to avoid repeated proxy access

**File:** `src/app/admin/staff/[staffId]/hours/page.tsx`

In Next.js 15 + React 18, `params` in client components is wrapped in a Proxy. Accessing
`params.staffId` multiple times per render (once in the JSX, once in the `useEffect` dep array)
triggers the "Cannot update a component while rendering a different component" warning — the
Proxy notifies the Next.js dev overlay on each access, which tries to setState mid-render.
Fixed by reading `params.staffId` once at the top of the component and using the local
`staffId` variable everywhere.

```diff
+const staffId = params.staffId;
 ...
-const res = await fetch(`/api/staff/${params.staffId}`);
+const res = await fetch(`/api/staff/${staffId}`);
-}, [params.staffId]);
+}, [staffId]);
```
